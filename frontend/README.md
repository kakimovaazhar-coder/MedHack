# MedRep

React + TypeScript. Микрофон, загрузка аудио и три панели: история, разговор, бланк.

## Запуск

Node.js 22.12+. Из корня репозитория:

```sh
npm --prefix frontend ci
npm --prefix frontend run dev
```

Открыть http://127.0.0.1:5173. Backend ожидается на `127.0.0.1:8000`.
Для другого сервера задать `VITE_API_URL=https://your-backend/api` в `frontend/.env.local`.
Секреты и ключи остаются на backend.

## Демо без сервера

```sh
npm --prefix frontend run dev:demo
```

Или открыть http://127.0.0.1:5173/?demo=1. Реплики вымышленного приёма появляются по очереди, бланк заполняется по мере разговора.
В заголовке разговора — пауза и повтор демо. Поиск в истории находит слова и даты.
Демо не обращается к API, микрофону или внешней LLM до явного запуска записи/загрузки.
Исправьте поле, отметьте «Проверено», скачайте настоящий `.docx` и откройте его в Word.
Для пустого рабочего экрана используйте адрес без `?demo=1`.

## Настоящий приём

1. Нажать «Начать запись» и разрешить микрофон, либо «Добавить аудио».
2. Завершить запись, дождаться обработки и проверить бланк. Правки врача не перезаписываются автоматически.
3. Отметить «Проверено» и скачать Word.

Для прошлой консультации — «Добавить прошлую запись» в левой панели.
Язык определяется автоматически. WAV, MP3, M4A, WebM, OGG, FLAC, AAC, MP4; до 30 МБ.
Временные задания сохраняются при прерывании ожидания: «Продолжить обработку файла»
не загружает аудио заново. Невалидные файлы и сетевые ошибки показаны в интерфейсе.

Микрофону нужен localhost или HTTPS и браузер с AudioWorklet. В backend должны быть
включены `MEDHUB_DEMO_ENABLED=true` и настроен `MEDHUB_WHISPERX_BASE_URL`.
Настройка речи/LLM — [docs/demo-workspace.md](../docs/demo-workspace.md).
Frontend использует готовый `/api/workspaces`, ревизии, аудиозадания и `/analyze`.
Для микрофона предпочтителен `/api/live/transcribe`; при 404/405 независимые WAV-фрагменты
идут через существующий workspace API. Новые backend-маршруты не обязательны.
Роли выводятся из данных сервера и явных речевых признаков; неоднозначные реплики остаются без роли.

## Проверка перед показом

```sh
npm --prefix frontend run check
```

Проверяются TypeScript/production-сборка, форматирование, поля/источники, Word,
аудиофрагменты, загрузка и восстановление задания после обрыва ответа.
В браузере проверены: пример, правки, подтверждение, Word, узкий экран и загрузка WAV
через неизменённый backend `medhub-demo` с локальной тестовой расшифровкой.
Тестовая расшифровка не подтверждает качество реального WhisperX или доступность серверов команды.

## Docker

```sh
docker compose -f compose.yaml -f compose.frontend.yaml up --build
```

Открыть http://127.0.0.1:8080, для примера — http://127.0.0.1:8080/?demo=1.
Overlay добавляет frontend к существующему backend; его исходники не изменены.
Docker daemon в текущей среде проверки не запущен: конфигурация проверена, контейнерный запуск не подтверждён.

## Данные

Документ и правки находятся в памяти вкладки; перед закрытием скачайте Word.
Автосохранения в localStorage нет. Серверные временные сессии удаляются после обработки
либо по TTL backend. Полный бланк содержит 13 разделов; серверный контракт содержит
шесть укрупнённых полей. Frontend сохраняет детальный DOCX локально. Для настоящей МИС требуется шлюз команды (см. ниже).
При настроенном OpenAI текст автоматически передаётся сервером в LLM; надёжная
деперсонализация и производственная авторизация не реализованы. Для показа используйте учебные данные.

## Кнопка МИС

«Отправить в МИС» доступна после завершения обработки и отметки «Проверено».
В учебном примере это явно обозначенная локальная демонстрация без передачи данных.
Исходный backend имеет только mock-экспорт; `/workspaces/.../export` скачивает JSON,
поэтому он не используется как подтверждение доставки в МИС.

Для реальной отправки команда может задать `VITE_MIS_EXPORT_URL=/api/mis/export`
в окружении frontend при сборке. Это контракт для подключения шлюза, не готовый
маршрут исходного backend. Без настройки интерфейс сообщает «МИС пока не подключена».
Frontend выполняет POST с `Idempotency-Key` и JSON:

```json
{
  "metadata": { "date": "2026-09-30", "name": "", "iin": "", "doctor": "" },
  "fields": { "complaints": "...", "illness_history": "..." },
  "vitals": { "height_cm": "...", "weight_kg": "..." },
  "reviewed": true
}
```

`fields` содержит все 13 разделов `TemplateValues`, `vitals` — все 8 показателей.
Успех показывается только после ответа шлюза `{"status":"sent","receipt_id":"..."}`.
Повтор неизменённого документа использует тот же ключ; шлюз обязан обрабатывать его
идемпотентно, проверять доступ и определять правильную карточку пациента.
Редактирование бланка снимает отметку «Проверено». Секреты МИС хранятся на сервере.
