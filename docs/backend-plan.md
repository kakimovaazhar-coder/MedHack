# План backend и параллельной разработки

## Стек и основание

В исходном задании UMC допустимы Python (FastAPI/Django), TypeScript NestJS или Go
для backend; React/Vue/Angular/TypeScript для frontend. Docker и Docker Compose обязательны.
Выбраны **Python 3.12 + FastAPI**, **React + TypeScript**. WhisperX — на компьютере
команды с подходящим оборудованием; OpenAI LLM — по API, модель не устанавливается локально.

## Полный целевой сценарий

1. Frontend создаёт консультацию с выбранным врачом `patient_id`.
2. Backend принимает аудио, проверяет тип/размер/длительность, возвращает задание `202`.
3. Обработчик WhisperX возвращает транскрипт с временными отметками.
4. Локальный модуль маскирует персональные данные. При сомнении требуется проверка.
5. OpenAI получает только подготовленный текст и схему. Ответ валидируется.
6. Frontend получает готовый черновик, врач сохраняет правки и подтверждает версию.
7. Адаптер МИС передаёт подтверждённую версию и сохраняет квитанцию получателя.

Аудио, PII, OpenAI и сетевой адаптер МИС — **следующие этапы**, не готовые возможности.
Сегодня `/demo` подставляет синтетические данные; `/audio` возвращает 503;
экспорт в деморежиме создаёт локальную mock-квитанцию без сетевого вызова.

## Что готово в скелете

| Блок | Реализация | Ограничение |
|---|---|---|
| API | Маршруты, модели, ошибки, Swagger, CORS | Нет авторизации |
| Форма | SQLite, правки, версии, подтверждение | Нет врачей/клиник и разграничения доступа |
| Задания | Опрос, демо, явная ошибка после перезапуска | Нет устойчивой очереди |
| AI pipeline | Интерфейсы speech → PII → LLM | Провайдеры отключены |
| МИС | Mock-квитанция, повтор одной версии без дубликата | Нет HTTP-передачи |
| Контракт | OpenAPI, TS-клиент и типы, JSON-примеры | Frontend ещё не создан |
| Docker | Образ и Compose backend | GPU и frontend пока не входят |

## Следующие задачи

### B1. WhisperX и загрузка аудио

Реализовать `SpeechProvider` в `integrations/whisperx.py`. Согласовать ОС/GPU и запуск
рядом с backend либо через HTTP. Проверить WAV/WebM из браузера, добавить ffmpeg,
ограничить размер и длительность, удалять временные файлы, обновлять статусы задания.
Русский, казахский и смешанную речь проверить отдельно. Не обещать точность заранее.
Критерий: собственная синтетическая запись даёт свой транскрипт через API.

### B2. Маскирование персональных данных

Реализовать `PiiMasker` в `integrations/pii.py`: ИИН, контакты, ФИО и другие сущности.
Regex не гарантирует полного удаления идентификаторов. При сомнении блокировать
облачный вызов и добавлять проверку. Не логировать исходный текст.
Критерий: тестовые идентификаторы не попадают в запрос OpenAI, сомнение не скрывается.

### B3. OpenAI

Реализовать `StructuringProvider` в `integrations/openai.py`: ключ только на backend,
явная настройка `OPENAI_MODEL`, Structured Outputs, обработка отказа/timeout/rate limit.
Отсутствующий факт → null; сохранять отрицания и неопределённость; различать уже
принимаемое лекарство и новое назначение. Не придумывать диагнозы/дозировки.
Добавить привязку полей к репликам источника с согласованием расширения API.
Критерий: speech → PII → OpenAI → проверка ответа → редактируемая форма.

### B4. HTTP mock API МИС

Реализовать `MisProvider` и отдельный сервис mock МИС в Compose. Передавать выбранного
пациента и подтверждённые правки. Идемпотентность по `(consultation_id, revision)`.
Timeout не считать успехом; учитывать изменения формы во время запроса.
Критерий: документ сохранён принимающим API, повтор не создаёт дубликат, отключённый
сервис даёт ошибку. Это не интеграция с реальной клиникой.

### B5. Доступ и интеграционный стенд

До реальных данных: авторизация, доступ врача/клиники, хранение и удаление данных,
защищённый транспорт. CORS не является авторизацией. Пока только синтетические данные.
Подключить frontend к backend; добавить его сервис в Compose; проверить запись
микрофона в браузере (для удалённого адреса потребуется HTTPS) и полный сценарий.

## Разделение работы

| Участник | Зона | Можно начинать сейчас |
|---|---|---|
| Frontend | `frontend/` | Запись, шесть полей, статусы, правки, подтверждение |
| Backend | `api.py`, `services/`, `repository.py` | Загрузка, задания, МИС |
| AI | `integrations/` | WhisperX, PII, OpenAI по интерфейсам |
| Интегратор | `contracts/`, Compose, CI | Контракт API и стенд |

Короткие ветки и PR. Изменение `schemas.py` согласуется, OpenAPI и TS-типы обновляются
в том же PR. Frontend и backend используют одну версию контракта. Зависимости
зафиксированы; секреты, записи пациентов, базы и веса моделей не коммитим.
