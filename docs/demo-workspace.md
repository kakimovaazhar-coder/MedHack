# Демо: аудиозаписи → история → лист консультации

## Запуск здесь

Из корня репозитория, Python 3.12 и Node 22.12+:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements-dev.lock
Copy-Item .env.example .env
# Заполнить OPENAI_API_KEY только в локальном .env. Не публиковать файл.
.venv\Scripts\python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --no-access-log
```

В другом терминале:

```powershell
npm --prefix frontend ci
npm --prefix frontend run dev
```

Интерфейс: http://127.0.0.1:5173. Документация API: http://127.0.0.1:8000/docs.
Не перезаписывайте существующий `.env` командой копирования. На подготовленном рабочем
компьютере окружение уже установлено через uv; повторная установка не нужна.

## Порядок демо

1. Откройте синтетический пример или загрузите прошлые аудиозаписи, затем текущую.
2. Проверьте расшифровки. Укажите роли врач/пациент и сохраните исправления.
   Speaker ID из диаризации сам по себе не определяет роль.
3. Укажите тему, например «анемия», или оставьте пустой для анализа текущей речи.
4. При использовании OpenAI проверьте текст и разрешите его отправку флажком.
5. «Собрать форму»: в центре релевантная история и прошлые рекомендации с цитатами,
   справа — шесть редактируемых полей текущего приёма.
6. В калькуляторе проверьте рост, вес и показатели. Выберите/введите препарат.
   После проверки перенесите расчёт в рекомендации справа.
7. Исправьте форму, сохраните правки, подтвердите и скачайте JSON.
   Это скачивание документа, не отправка в настоящую МИС.

Повторная сборка заменяет поля после предупреждения. Изменение источника делает старую
форму неактуальной: подтверждение блокируется до повторной сборки. Каждая запись
имеет дату, тип «история/текущий», источник «аудио/текст/пример» и реплики.

## WhisperX на отдельном компьютере

WhisperX — отдельный Python-сервис. Он не установлен вместе с лёгким backend.
Требуются Python 3.12, ffmpeg в PATH и ресурсы для выбранной модели.

```powershell
python -m venv .venv-speech
.venv-speech\Scripts\python -m pip install -r speech_worker/requirements.txt
$env:WHISPERX_DEVICE = 'cpu'
$env:WHISPERX_COMPUTE_TYPE = 'int8'
$env:WHISPERX_MODEL = 'small'
$env:WHISPERX_API_TOKEN = '<общий секрет backend и worker>'
.venv-speech\Scripts\python -m uvicorn speech_worker.app:app --host 127.0.0.1 --port 9000 --no-access-log
```

Для соединения разных компьютеров в доверенной сети поменяйте host на 0.0.0.0,
ограничьте входящие соединения firewall компьютером backend. Не публикуйте этот
демо-сервис в Интернет. В корневом `.env` компьютера backend:

```dotenv
MEDHUB_WHISPERX_BASE_URL=http://<адрес-компьютера-с-WhisperX>:9000
MEDHUB_WHISPERX_API_TOKEN=<тот же секрет>
OPENAI_MODEL=gpt-4.1-mini
OPENAI_API_KEY=<свой ключ>
```

Перезапустите backend. `/health` worker показывает наличие пакета/ffmpeg и загрузку
модели; `model_loaded=false` до первого запроса нормально. Первый запрос скачивает
веса моделей и может занять больше времени. CPU-режим медленный. Для GPU подберите
совместимые PyTorch/CUDA по [WhisperX](https://github.com/m-bain/whisperX).
Зависимости worker ограничены веткой WhisperX 3.8, точный набор нужно зафиксировать
на целевом компьютере после проверки CPU/GPU. В этом изменении реальный inference
WhisperX на целевом железе ещё не проверялся.

Без `HF_TOKEN` сервис отдаёт фрагменты с ролью unknown. Опциональный `HF_TOKEN`
включает диаризацию после принятия условий модели
`pyannote/speaker-diarization-community-1`. Роли всё равно подтверждает врач.
Выравнивание слов не выполняется; используются временные отметки сегментов.

Лимиты: 30 МБ, 30 минут, 12 записей на сессию, один текущий приём.
Загрузка нескольких прошлых аудио выполняется последовательно. На backend аудио
буферизуется в памяти, worker пишет временный файл и удаляет его после обработки.
Аварийное завершение ОС может оставить временный файл worker; это не защищённое стирание.
При удалении сессии незавершённый запрос к worker не отменяется, его ответ отбрасывается.

## Frontend на другом компьютере

В `frontend/.env.local` укажите `VITE_API_URL=http://<backend>:8000/api` и перезапустите Vite.
Backend запустите на адресе доверенной LAN; добавьте точный адрес frontend в
`MEDHUB_CORS_ORIGINS`. Ключ OpenAI находится только на backend. В коде frontend нет секретов.
На одном компьютере Vite проксирует `/api` на 127.0.0.1:8000.

## Что делает OpenAI

Используется Responses API, `store=false`, структурированный JSON с идентификаторами
исходных реплик. Модель выбирает релевантную историю и распределяет реплики по полям.
Backend проверяет существование источников, тип текущий/история и роль говорящего,
после чего копирует исходные цитаты. Это ограничивает выдумывание фактов, но не заменяет
проверку врачом: модель может ошибиться при выборе и классификации цитаты.
Численные вычисления выполняются отдельно через Decimal.

В OpenAI отправляются текст реплик, роли, даты и тема, без файла аудио, названий
записей или идентификатора пациента. Текст может содержать персональные данные:
автоматическая деперсонализация пока не реализована. `store=false` не означает
Zero Data Retention; действуют настройки и правила провайдера.
См. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
и [обработка данных](https://developers.openai.com/api/docs/guides/your-data).

Без ключа доступен явно обозначенный режим локальных правил. Ошибка OpenAI/WhisperX
не подменяется синтетическим результатом. Команда ручного платного smoke-теста:
`python scripts/test_openai.py` — отправляет только встроенный вымышленный диалог.

## Расчёты

ИМТ = масса (кг) / рост (м)². Категории и диагноз по ИМТ не выводятся.
Источник: [CDC](https://www.cdc.gov/bmi/about/index.html).

Для демо анемии: общий дефицит железа (мг) = масса (кг) ×
(целевой Hb − актуальный Hb) (г/л) × 0,24 + запас железа (мг).
Источник и область применения: [SmPC Venofer, раздел 4.2](https://www.medicines.org.uk/emc/product/5911/smpc).
Это общая потребность в элементарном железе, не разовая/суточная доза, не схема
приёма таблеток или инфузий. Препарат остаётся выбором врача; название не включает
автоматически его ограничения, противопоказания, объём и скорость введения.
Применимость формулы, расчётную массу и целевые параметры проверяет врач.
Настоящую инструкцию конкретного препарата нужно сверять отдельно.

Числовые значения с явно указанными единицами находятся в тексте регулярными
выражениями. Поддерживаются см/м, кг, Hb в г/л или г/дл. Числа, записанные словами,
не разбираются. При конфликтующих значениях поле остаётся пустым. Исторический Hb
виден отдельно с датой и не подставляется автоматически. Значения 150 г/л и 500 мг
в синтетическом примере произносит вымышленный врач; это не глобальные настройки.
Подтверждение параметров требуется до переноса в рекомендации. Изменение любого
параметра сбрасывает подтверждение в интерфейсе.

## Контракт и проверки

Новые ручки: `/api/workspaces`, `/records`, `/audio`, `/analyze`, `/form`,
`/calculate`, `/calculation/apply`, `/confirm`, `/export`.
OpenAPI и `contracts/api.d.ts` генерируются из backend; frontend импортирует эти типы.
Запросы изменений передают `expected_revision`. Аудио отправляется сырым телом
`application/octet-stream`; метаданные — query, поэтому запускайте без access log.
Старые `/api/consultations` остаются отдельным синтетическим SQLite-сценарием.

```powershell
.venv\Scripts\python scripts/export_contracts.py
npm run contracts:types
npm run contracts:check
.venv\Scripts\python -m pytest backend/tests -q
npm --prefix frontend run build
```

Для pytest из корня нужен `PYTHONPATH=backend`; проще запускать из каталога backend.
Демо использует память одного процесса; запускайте один uvicorn worker.
Нет авторизации пользователей, интеграции с настоящей МИС и промышленного хранилища.
Сессии очищаются по TTL (час, проверка каждые 30 сек.), вручную или при перезапуске.
Обновление страницы создаёт новую сессию; старая исчезнет по TTL.
Не используется localStorage для медицинских данных. Клиентская страница может
показывать уже полученный текст до закрытия вкладки; TTL — срок хранения на backend.
